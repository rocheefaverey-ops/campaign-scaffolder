# TanStack Start + Unity Campaign Template

Campaign frontend built on TanStack Start with embedded Unity WebGL game. **Contains only mandatory code.** Optional module code lives in `../../modules/`.

## Stack

- **Framework:** TanStack Start (React Router v1) + React 19, SSR via Nitro
- **Bundler:** Vite 7
- **UI:** Tailwind CSS 4, SCSS Modules
- **State:** Zustand (game state), TanStack server functions (CAPE data)
- **CMS:** CAPE (JSON over CDN, cached server-side via `CapeMiddleware`)
- **Game bridge:** `components/game/UnityContext.tsx` — React Context wrapping Unity WebGL
- **Forms:** TanStack Form + Zod validation
- **Animations:** Motion (Framer Motion)
- **Logging:** Winston + optional GCP Cloud Logging

## Dev Commands

```bash
pnpm dev             # Vite dev server on :3000
pnpm build           # Production build → .output/server/
pnpm start           # Production server (node --env-file=.env .output/server/index.mjs)
pnpm lint            # ESLint
pnpm ts-compile      # TypeScript type check (no emit)
```

## Architecture Principles

1. **File-based routing** — `src/routes/` with TanStack Router; `__root.tsx` is the root layout.
2. **Loaders fetch data** — dedicated loaders in `src/loaders/` run during route pre-load; components read via `useLoaderData()`.
3. **Server functions only** — CAPE data fetched via `createServerFn()` middleware; client components never call `fetch()` directly.
4. **UnityContext** is the single source of truth for game state — Zustand store (`useUnityStore`) for scores/results.
5. **CAPE data** fetched once via `CapeMiddleware` (5-min TTL), flows down through loaders → components.
6. **CSP nonce** generated by `SecurityMiddleware` → injected into `<script>` tags in `__root.tsx`.
7. **`src/server/`** is server-only — CAPE provider, middleware, API handlers. No React/JSX.
8. **`src/components/`** is the UI layer — blocks, containers, forms, game bridge.

## CAPE Integration

### Data flow
```
CapeMiddleware (server, 5-min cache)
  → CapeProvider.ts (createServerFn wrappers)
    → getCapeProperty()    — raw property access (returns CapeProperty wrapper)
    → getCapeCopy()        — multilingual copy strings
    → getCapeCopyMapUnity()— bulk copy export for Unity game translations
```

### CAPE URL pattern
`${CAPE_BASE_URL}/${CAPE_CAMPAIGN_ID}_${CAPE_CAMPAIGN_MARKET}.json`

### Model path conventions
- `settings.*` / `general.*` — campaign-global (branding, menu config)
- `copy.{pageId}.*` — page-scoped multilingual text
- `files.{pageId}.*` — page-scoped assets (images, videos)
- `desktop.*` — desktop wrapper (logo, background)

### DesignTokenInjector
Always-on component that injects CAPE branding settings as CSS custom properties. Overrides `globals.css` defaults (`--color-primary`, `--color-secondary`, etc.). Not optional.

## Unity Game Bridge

`src/components/game/UnityContext.tsx` wraps the Unity WebGL instance:

| Method | Purpose |
|--------|---------|
| `initializeUnity()` | Load Unity loader script, create WebGL instance |
| `preloadScene()` | Trigger Addressables preload via `SendMessage('WebService', 'SetScene')` |
| `loadScene()` | Load scene with data |
| `startGame()` | `SendMessage('GameService', 'StartGame')` |
| `sendMessage(obj, method, data?)` | Direct bridge to Unity C# layer |
| `addEventListener(event, cb)` | Subscribe to Unity events |

Events: `sceneLoaded`, `addressableLoaded`, `ready`, `loading`, `start`, `end`, `apiRequest`, `navigation`, `tracking`

Game state stored in `useUnityStore` (Zustand) — scores, results, session data.

## Key Directories

```
src/
├── components/       # UI — buttons, containers, forms, game, design-tokens, visuals
├── hooks/            # useUnity, useApi, useTracking, stores/useUnityStore
├── interfaces/       # TypeScript interfaces (CAPE, Unity, Forms, API)
├── loaders/          # Route data loaders (RootLoader, LandingLoader, GameLoader…)
├── lib/              # Client-side utilities (cape.ts for client CAPE access)
├── routes/           # File-based routes + API endpoints (api/cape.ts, api/unity.ts)
├── server/           # Server-only code
│   ├── api/          # API error handling, session management
│   ├── cape/         # CapeMiddleware, CapeProvider, CapeProperty wrapper
│   └── middleware/   # Security (CSP nonce), error reporting, flow validation
├── utils/            # Helpers (getPlatform, parseNumber, etc.)
└── globals.css       # Tailwind 4 imports + design token custom properties
```

## Styling

- **Tailwind 4** via `@tailwindcss/vite` plugin — custom `@theme` block in `globals.css` (no tailwind.config.js)
- **SCSS Modules** — Vite auto-prepends `@use "~/assets/styles/main.scss" as *;` to every `.module.scss`
- **Design tokens** as CSS custom properties — overridden at runtime by `DesignTokenInjector`

## Environment Variables

See `.env.example`. Minimum required:
- `CAPE_BASE_URL`, `CAPE_CAMPAIGN_ID`, `CAPE_CAMPAIGN_MARKET`
- `UNITY_SCENE_KEY` — default scene to load
- `VITE_ENVIRONMENT` — build environment (dev, staging, prod)

Unity DPR tuning: `VITE_UNITY_DESKTOP_DPR`, `VITE_UNITY_MIN_DPR` (default 1), `VITE_UNITY_MAX_DPR` (default 3)

## Module Slots

`src/components/` is populated by the CLI when modules are selected. Each module injects into:
- `src/routes/` — page routes
- `src/server/` — server functions / API handlers
- `src/loaders/` — data loaders
